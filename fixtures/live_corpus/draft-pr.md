# Draft PR作成・更新スキル

このスキルは、Gitワークツリーでの実装完了後に、変更をコミットしてリモートに反映し、GitHub上でDraft PRを作成または更新するための手順を提供します。

## ワークフロー

### 1. 既存PRの確認
まず、現在のブランチに紐づくPRが既に存在するか確認します。

```bash
# 現在のブランチ名を取得
BRANCH_NAME=$(git branch --show-current)

# ブランチに紐づくPRを検索
gh pr list --head "$BRANCH_NAME" --json number,title,body --no-pager
```

### 2. 変更のコミットとプッシュ
既存PRの有無に関わらず、変更をコミットしてプッシュします。

1. **ステージング**: `git add .`
2. **内容確認**: `git status` および `git diff --stat`
3. **コミット**: 日本語で詳細な説明を含むコミットメッセージを作成。
   - 使用しているAIモデル名（例: Gemini 3 Flash (Preview)）を明記。
4. **プッシュ**:
   - 新規の場合: `git push -u origin "$BRANCH_NAME"`
   - 更新の場合: `git push`

### 3. PRの作成または更新

#### 技術的な説明の生成
以下のコマンドでベースブランチ（通常は `develop` または `main`）との全差分を確認し、PR本文（概要、背景、実装内容、テスト内容等）を日本語で構築します。

```bash
# ベースブランチとの差分確認
git diff develop...HEAD
```

#### 新規作成（PRが存在しない場合）
```bash
gh pr create --draft --base develop --title "タイトル" --body "生成した本文"
```
※本文の冒頭には必ず以下の **ユーザー入力枠** を含めてください。
```markdown
<!-- ユーザー入力枠 / Start -->

<!-- ユーザー入力枠 / End -->
```

#### 更新（PRが存在する場合）
1. 既存PRの本文を取得: `gh pr view <PR番号> --json body`
2. **既存のユーザー入力枠（StartからEndまで）の内容を抽出し、新しい本文の冒頭にそのまま維持します。**
3. 残りの技術的な説明部分を最新の差分に基づき再作成して結合します。
4. PRを更新:
```bash
gh pr edit <PR番号> --title "新しいタイトル" --body "新しい本文"
```

### 4. CIの監視と修正 (CI Verify & Fix Loop)
PR作成・更新後は必ずCIステータスを確認し、失敗している場合は修正を行います。

1. **ステータス監視**: `gh pr checks --watch` を実行してCIの完了を待ちます。
2. **失敗時の原因特定**:
   - `gh pr checks` で失敗しているジョブを特定します。
   - `gh run view <run_id>` またはジョブIDを使用して失敗ログを取得します。
3. **修正と再プッシュ**:
   - ログから原因を特定し、コードを修正します。
   - 修正をプッシュし、再び `gh pr checks --watch` で結果を待ちます。
4. **ループ**: CIがすべてパスするか、手動での介入が必要と判断するまでこれを繰り返します。

## 注意事項

- **⚠️ 重要**: `gh pr view` だけでPRを特定せず、必ず `gh pr list --head <ブランチ名>` を使用して、現在のブランチに正しいPRを特定してください。
- **言語**: コミットメッセージおよびPRのタイトル・本文はすべて日本語で記述してください。
- **ベースブランチ**: `kaijin-web` は `develop`、`buddy-terraform` は `main` をデフォルトのベースとして使用してください。
- **事前確認**: フォーマットチェックやテストが成功していることを確認した上で実行してください。

## PR本文の標準構成
1. ユーザー入力枠（必須）
2. 概要
3. 背景
4. 実装内容（詳細）
5. 動作フロー
6. テスト内容
7. 影響範囲
8. その他の注意事項
